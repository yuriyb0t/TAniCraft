# Архитектура

Документ описывает, как устроен код TAniCraft: владение состоянием, поток данных,
кэши, undo и точки расширения. Читать вместе с [`AGENTS.md`](../AGENTS.md).

---

## 1. Общая картина

```
┌─────────────────────────────────────────────────────────────────┐
│ eframe (glow / OpenGL)                                          │
│  └─ App (src/app.rs)  ← единственный владелец состояния         │
│      ├─ Document (src/doc.rs)   модель: слои → кадры → Bitmap   │
│      ├─ Theme    (src/theme.rs) палитра и стиль egui            │
│      └─ UI-панели (methods on App):                             │
│          menu_bar / tab_bar / status_bar / timeline_panel /     │
│          tools_panel / properties_panel / stage_ui / dialogs    │
└─────────────────────────────────────────────────────────────────┘
```

Никакого глобального состояния, никаких `static mut`: всё живёт в `App`, панели —
это методы `impl App`, которые получают `&mut self` и `&mut egui::Ui`.

`App::update` (реализация `eframe::App`) вызывается каждый кадр и собирает UI
сверху вниз в фиксированном порядке. Порядок определяет, кто получает место на
экране: `TopBottomPanel`/`SidePanel` «съедают» края, `CentralPanel` забирает остаток.

### Порядок панелей

```rust
menu_bar         // top, 26 px
tab_bar          // top, 28 px
status_bar       // bottom, 22 px
timeline_panel   // bottom, 120..620 px, resizable
tools_panel      // right, 62 px, fixed
properties_panel // right, 210..380 px (default 252), resizable
CentralPanel     // остальное — stage
dialogs          // поверх всего
```

Именно поэтому таймлайн и статус-бар растягиваются на всю ширину окна, а
инструменты/свойства — только над ними: так выглядит рабочее пространство Animate.

## 2. Модель данных (`doc.rs`)

```
Document
 ├─ name / width / height / fps / bg[4]
 └─ layers: Vec<Layer>           // индекс 0 = нижний слой
      ├─ uid: u64                // стабильный id для текстур/undo
      ├─ name / visible / locked
      └─ frames: Vec<Frame>
           ├─ kind: Empty | Hold | Key
           └─ bitmap: Option<Bitmap>   // только у Key
```

### Семантика кадров

| kind | Что значит | Есть bitmap |
|---|---|---|
| `Empty` | рисок нет и ничего не «держится» слева | нет |
| `Hold` | продолжает ближайший ключевой кадр слева | нет (берётся из key) |
| `Key` | собственный рисунок (может быть пустым) | да |

`Layer::effective_key(f)` идёт назад от `f` до первого `Key`, останавливаясь на
`Empty`. `Layer::bitmap_at(f)` возвращает рисунок этого ключевого кадра.

### Bitmap

```rust
Bitmap { w, h, data: Arc<Vec<u8>>, rev: u64 }
```

- Формат пикселей: **premultiplied RGBA8**, порядок байт R,G,B,A.
- `Arc` + `Arc::make_mut` в `data_mut()` = copy-on-write. Клон битмапа бесплатный,
  пока никто не пишет. Это основа дешёвых undo-снимков и клонирования слоёв.
- `rev` инкрементится при любой мутации. Кэш текстур и кэш «пустой/непустой»
  сверяются по `rev`, поэтому ручная инвалидация не нужна.
- Конвертация в straight alpha — только на границах (PNG-экспорт/сохранение).

### Штрих кисти

`Bitmap::stamp(cx, cy, radius, hardness, color, alpha, erase)`:

1. bbox штампа обрезается по границам битмапа;
2. для каждого пикселя считается расстояние до центра;
3. покрытие: `1.0` внутри `radius * hardness`, затем smoothstep к краю;
4. `alpha` = `opacity * coverage`;
5. кисть: `dst = dst * (1 - a) + src_premult * a`;
   ластик: `dst *= (1 - a)` по всем 4 каналам (включая альфу — «в прозрачность»).

Возвращает `DirtyRect`, который используется для `TextureHandle::set_partial`.

`Document::flatten(frame)` композитит видимые слои поверх фона (нужно для экспорта).

## 3. Состояние приложения (`app.rs`)

Группы полей `App`:

| Группа | Поля |
|---|---|
| Документ | `doc`, `path`, `dirty` |
| Инструмент | `tool`, `brush`, `eraser`, `onion` |
| Вид | `view` (`offset`, `zoom`, `fitted`), `stage_rect` |
| Таймлайн | `current_frame`, `sel_layer`, `tl_scroll_x/y`, `playing`, `looping`, `play_accum` |
| История | `history`, `redo_stack` (`UndoAction`) |
| Кэши | `textures: HashMap<(uid, key), TexEntry>`, `tex_epoch`, `blank_cache` |
| Рисование | `stroke: Option<Stroke>` |
| UI | `status`, флаги диалогов, `menu_target`, `title_cache`, `want_close` |

### Команды

Все действия пользователя сведены к `enum Cmd` и `App::exec(Cmd)`. Это упрощает
добавление пунктов меню, кнопок и горячих клавиш: каждый вызывает `request(cmd)`
(проверка несохранённых изменений) или `exec(cmd)` напрямую.

Новая фича = новый вариант `Cmd` + ветка в `exec` + пункт меню/кнопка.

### Undo/Redo

```rust
enum UndoAction {
    Pixels { layer_uid, frame, before: Bitmap, after: Bitmap },
    Doc    { before: Box<Document>, after: Box<Document> },
}
```

- `commit(before_doc)` — для структурных изменений (кадры, слои, свойства).
- `push_pixels(uid, frame, before, after)` — для штрихов.
- Лимит 40 шагов, `redo_stack` очищается при новой правке.
- После undo/redo обязателен `tex_epoch += 1` и `clamp_selection()`.

`Document` клонируется дёшево, потому что все `Bitmap` — `Arc`. При следующей
мутации `Arc::make_mut` создаст копию только изменяемого кадра, не трогая снимок
в истории.

## 4. Рендер холста (`canvas.rs`)

`App::stage_ui`:

1. `stage_rect` = доступная область; первый кадр — `fit_view()`.
2. Рисуется паста (`#1f1f1f`), тень и фон документа (шахматка при альфе < 255).
3. Он-скины: собираются предыдущие/следующие **ключевые** кадры каждого видимого
   слоя, рисуются с `Color32::from_white_alpha(alpha)`.
4. Слои снизу вверх: `texture_for(...)` → `painter.image(...)`.
5. Рамка документа.
6. Ввод: зум (Ctrl+колесо), пан (колесо/пробел/средняя кнопка/Hand), кисть.
7. Курсор-кружок размера кисти (белый + тёмный контур для контраста).

### Текстурный кэш

```rust
TexEntry { handle: TextureHandle, rev: u64, epoch: u64 }
```

- Ключ — `(layer_uid, keyframe_index)`, а не номер кадра: все Hold-кадры одного
  спана переиспользуют одну текстуру.
- Попадание: `rev == bitmap.rev && epoch == app.tex_epoch`.
- Промах: полная загрузка `ColorImage` (premultiplied).
- Во время штриха — `set_partial` по dirty-rect, без полной перезагрузки.
- `tex_epoch` инкрементится при undo/redo, структурных операциях, смене документа,
  resize — это гарантирует перезагрузку даже при совпадении `rev`.

### Почему не CPU-композит

Слои композитит GPU (каждый слой — отдельная текстура с альфой). CPU-композит
нужен только для экспорта PNG (`Document::flatten`). Это даёт 20+ слоёв без
просадок.

## 5. Таймлайн (`timeline.rs`)

Геометрия (константы сверху файла):

```
FRAME_W = 16 px   ROW_H = 22 px   RULER_H = 20 px   LEFT_W = 208 px
```

Всё рисуется вручную в два прямоугольника: `left_rows` (имена слоёв) и `rows`
(сетка кадров), с общим вертикальным скроллом `tl_scroll_y` и горизонтальным
`tl_scroll_x`. Слева есть фиксированный заголовок `LAYERS`, справа — фиксированная
линейка.

Порядок отрисовки:

1. фон и разделители;
2. скролл колесом (Shift — горизонтально), клампы;
3. интеракции: линейка (seek), сетка (выбор ячейки, double-click → keyframe,
   right-click → контекстное меню);
4. заголовок слоёв с кнопками (new/duplicate/delete/up/down);
5. линейка с номерами каждые 5 кадров;
6. `rows_meta` — предвычисленные `(frame, kind, blank, has_content)` на видимый
   диапазон. Нужен, чтобы не сканировать битмапы в цикле отрисовки;
7. ячейки: заливка по типу, точка ключевого кадра, выделение, разделители;
8. левая колонка: eye/lock/имя, контекстное меню;
9. плейхед и горизонтальный скроллбар.

### Кэш «пустой кадр»

`HashSet`-подобный `blank_cache: HashMap<(uid, frame), (rev, bool)>`. Проверка
`Bitmap::is_blank()` — O(w·h), поэтому её нельзя делать каждый кадр для каждой
ячейки. Кэш валидируется по `rev`; запись обновляется лениво. (Сейчас кэш не
чистится — см. TASKS, P2.)

## 6. Ввод

### Клавиатура

`App::handle_shortcuts` — единая точка. Если `ctx.wants_keyboard_input()` (фокус в
текстовом поле), шорткаты игнорируются. `modifiers.command` = Ctrl на Windows/Linux,
Cmd на macOS.

### Мышь

- Холст: `Sense::click_and_drag` на всей области; рисование начинается по
  `primary_pressed` внутри прямоугольника документа.
- Промежуточные точки берутся из `i.events` (`Event::PointerMoved`) — так штрих не
  «ломается» на быстром движении; если событий нет, используется `latest_pos`.
- Таймлайн: отдельные `ui.interact` для линейки/сетки/строк слоёв; hit-testing
  вручную по координатам.

## 7. Паттерны для borrow checker

egui требует `&mut Ui` и `&mut App` одновременно, поэтому в коде используются:

1. **Сбор данных до мутации.** Например, список `(uid, key, Bitmap)` собирается
   до вызова `self.texture_for(... &mut self)`.
2. **Disjoint field borrows.** `let doc = &self.doc; let cache = &mut self.blank_cache;`
   — легально, потому что поля разные.
3. **Локальные снимки значений** (`let scroll_x = self.tl_scroll_x;`) вместо
   замыканий, захватывающих `self` — иначе нельзя звать `&mut self` методы позже.
4. **Временное изъятие** (`self.stroke.take()`), обработка, возврат на место.

Если добавляете новый цикл отрисовки, который вызывает `&mut self` методы, сначала
соберите нужные данные в вектор.

## 8. Производительность

- Рисование: O(площадь штампа) на штамп, шаг — 10% диаметра. Для кисти 100 px это
  ~8k пикселей на штамп, десятки штампов в секунду — не проблема.
- Полная перезагрузка текстуры 1280×720 ≈ 3.7 МБ; происходит только при первом
  показе ключевого кадра или после undo.
- Playback: текстуры ключевых кадров кэшируются, поэтому после первого прохода
  анимация не грузит GPU.
- Таймлайн: рисуются только видимые ячейки (`i0..i1`, фильтр по `y`).

## 9. Точки расширения

| Фича | Куда добавить |
|---|---|
| Новый инструмент | вариант `Tool` → кнопка в `tools_panel` → ветка в `stage_ui` |
| Новая команда | вариант `Cmd` → ветка `exec` → меню/кнопка/шорткат |
| Новый тип кадра (tween) | `FrameKind` + `effective_key` + отрисовка в `timeline.rs` |
| Новый формат экспорта | функция в `doc.rs` + пункт меню File → Export |
| Панель (например, Color) | новый `SidePanel` в `App::update` + метод `*_panel` |
| Свойство слоя | поле в `Layer` + UI в `properties_content` + (при необходимости) формат файла |

При добавлении поля в `Document`/`Layer` не забыть:
- сериализацию в `DocFile`/`LayerFile` (+ `#[serde(default)]` для совместимости);
- `Document::new` и загрузку;
- сброс кэшей, если поле влияет на рендер.
