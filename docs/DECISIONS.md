# Архитектурные решения (ADR)

Короткие записи о решениях, которые **не** стоит менять случайно. Формат: контекст →
решение → последствия. Если решение пересматривается, добавляется новый ADR со
ссылкой на старый (старые не удаляются).

---

## ADR-001 · egui/eframe зафиксированы на 0.33.x

**Контекст.** Проект должен выглядеть как Adobe Animate: тёмные панели, ручной
таймлайн, ресайз панелей. В egui 0.34–0.37 изменились сигнатуры `App::update`,
поведение `TopBottomPanel`/`SidePanel` и API панелей; обновление требует переписать
весь UI-слой.

**Решение.** `eframe`/`egui` ровно `0.33.0`, рендер — `glow` (OpenGL).
Обновление — только отдельной задачей с полной перепроверкой UI.

**Последствия.** Стабильная вёрстка и предсказуемые скриншоты. Новые фичи egui
недоступны. При обновлении придётся править `app.rs`, `timeline.rs`, `canvas.rs`,
`dialogs.rs` и заново снимать скриншоты.

## ADR-002 · Растровый кадр на ключевой кадр (не вектор, не сцена)

**Контекст.** Нужен аниматор «как Animate», но с реально работающим рисованием на
старте. Векторная модель (шейпы, контуры, заливки) требует геометрического ядра и
заметно больше кода, чем бюджет прототипа.

**Решение.** Каждый ключевой кадр слоя — независимый растровый `Bitmap` размером с
документ. Hold-кадры ссылаются на ближайший ключевой слева. Слои композитится
поверх друг друга при отрисовке.

**Последствия.** Простая и быстрая реализация, идеальная для кисти/ластика. Нет
бесшовного масштабирования (растр «мылится»), нет символов/твинов. Тип кадра —
`FrameKind { Empty, Hold, Key }`; добавление tween-типов потребует расширения
`effective_key` и таймлайна. Отказ от векторного ядра зафиксирован осознанно.

## ADR-003 · Пиксели premultiplied RGBA8

**Контекст.** `egui::ColorImage` ожидает premultiplied RGBA. Смешивание кисти проще
и корректнее в premultiplied-пространстве (нет «ореолов» на полупрозрачных краях).

**Решение.** В памяти и в `ColorImage` — **premultiplied** RGBA8. На границах
(PNG-сохранение, экспорт) — конвертация в straight alpha
(`Bitmap::to_rgba_straight` / `from_rgba_straight`).

**Последствия.** Быстрая загрузка текстур без промежуточной конвертации. Любой новый
код, читающий `Bitmap::data()` напрямую, обязан помнить про premultiplied. Ошибка
здесь даёт тёмные/светлые каймы, а не падение — проверять визуально.

## ADR-004 · Битмапы — `Arc<Vec<u8>>` (copy-on-write)

**Контекст.** Undo хранит снимки документа, слои дублируются, текстуры кэшируются.
Копирование 1280×720×4 байт (3.7 МБ) на каждую операцию слишком дорого.

**Решение.** `Bitmap { w, h, data: Arc<Vec<u8>>, rev }`. Мутация только через
`data_mut()` → `Arc::make_mut` + `rev += 1`.

**Последствия.** Клон битмапа бесплатный, пока он не изменён; undo-снимок
`Document` стоит несколько `Arc`-инкрементов. Инвариант «мутация = новый `rev`»
нельзя нарушать: на нём держатся кэш текстур и `blank_cache`. Прямая запись в
`Arc::get_mut`/`as_mut` в обход `data_mut()` запрещена.

## ADR-005 · Собственный контейнер `.tcraft`

**Контекст.** Нужен один переносимый файл проекта без внешних зависимостей и без
сложных форматов (ZIP/XML). При этом кадры — PNG (сжатие обязательно).

**Решение.** Свой контейнер: magic `TACRAFT1`, `u32` длина JSON, JSON-манифест,
затем подряд блоки PNG (`u32` длина + данные). Спецификация —
[`FILE_FORMAT.md`](FILE_FORMAT.md).

**Последствия.** Простое чтение/запись без сторонних крейтов, кроме `png`.
Нет превью, дедупликации изображений и контрольных сумм. Формат версионируется
полем `version`; несовместимые изменения — только с повышением версии.

## ADR-006 · Рисование автоматически создаёт ключевой кадр

**Контекст.** В Adobe Animate рисование в Hold-кадре создаёт новый ключевой кадр,
но в пустом месте — требует явного F6/F7. Для прототипа важно, чтобы новичок мог
сразу рисовать в любом кадре.

**Решение.** `App::ensure_keyframe` при начале штриха: если кадр не `Key`, он
превращается в ключевой (для Hold — с копией удерживаемого рисунка, для Empty —
пустой).

**Последствия.** Осознанное отклонение от Animate: нельзя «случайно» нарисовать в
пустоте, но пропадает риск потерять штрих. Поведение описано в README и AGENTS.
Если понадобится точное поведение Animate — добавить настройку, а не менять молча.

## ADR-007 · Таймлайн рисуется вручную

**Контекст.** Нужны синхронные колонки слоёв и сетка кадров, фиксированная линейка,
плейхед поверх ячеек и точный hit-testing. `ScrollArea` с двумя синхронизируемыми
областями даёт рассинхрон на границе и «прыжки» при ресайзе.

**Решение.** Вся геометрия считается вручную: `FRAME_W = 16`, `ROW_H = 22`,
`RULER_H = 20`, `LEFT_W = 208`; скролл — свои поля `tl_scroll_x/y`, отрисовка только
видимых ячеек.

**Последствия.** Полный контроль над видом и поведением, но больше кода и ручной
hit-testing. Не заменять на `ScrollArea` и не переносить в `Context`-лейеры без
крайней необходимости.

## ADR-008 · Undo: снимки документа + снимки кадра

**Контекст.** Структурные операции (слои, кадры, свойства) затрагивают много полей;
штрихи — один битмап. Командный паттерн с `undo()` для каждой операции раздувает
код и легко оставляет баги.

**Решение.** `enum UndoAction { Doc { before, after }, Pixels { layer_uid, frame,
before, after } }`. Структурные правки — `App::commit(before_doc)`, штрихи —
`App::push_pixels(...)`. Лимит 40 шагов, `redo_stack` очищается при новой правке,
после undo/redo `tex_epoch += 1`.

**Последствия.** Простое и надёжное покрытие undo. Снимки дешевы благодаря ADR-004.
Минус — память под историю структурных правок (40 копий `Document`, но битмапы
разделены). Новая мутирующая операция обязана явно выбрать один из двух путей.

## ADR-009 · Интерфейс на английском

**Контекст.** Цель — визуальное сходство с Adobe Animate. Терминология Animate
(`Keyframe`, `Onion Skin`, `Properties`, `Timeline`) знакома пользователям.

**Решение.** Все подписи UI — на английском. Комментарии в коде, документация и
сообщения коммитов — на русском.

**Последствия.** Скриншоты легко сравнить с Animate. Локализация — отдельная задача
(ROADMAP, v0.6), английский остаётся языком по умолчанию. Не переводить UI
частично: смесь языков ломает впечатление.

## ADR-010 · Иконки только векторные, без ассетов

**Контекст.** Нужны иконки в стиле Adobe, но проект не должен тащить бинарные
ресурсы, шрифты-иконки или SVG-рендерер.

**Решение.** `enum Icon` + `icons::paint(painter, rect, icon, color)` в
`src/icons.rs`. Фигуры рисуются линиями/дугами в нормализованных координатах 0..1.

**Последствия.** Иконки масштабируются, перекрашиваются и не требуют файлов.
Добавление иконки — вариант enum + ветка `match`. Минус — сложные пиктограммы
писать долго; для них допустимы составные примитивы, но не внешние PNG/SVG.

## ADR-011 · Файловые диалоги — `rfd`, синхронно из UI-потока

**Контекст.** Нужны нативные диалоги открытия/сохранения на Windows/macOS/Linux.
Асинхронные варианты требуют каналов и усложняют состояние `App`.

**Решение.** `rfd` с блокирующими вызовами прямо из обработчика команды. На время
диалога кадр не рисуется — это приемлемо.

**Последствия.** Минимум кода и никаких «зависших» состояний. UI замирает на время
диалога; при больших файлах сохранение тоже блокирует поток. Если появится нужда —
перейти на `AsyncFileDialog` + канал, но это отдельный ADR.

## ADR-012 · Один документ за раз

**Контекст.** Вкладки, несколько документов и переключение между ними требуют
разделения `App` на «редактор» и «сессию», а также отдельного lifecycle для
текстур и undo на каждый документ.

**Решение.** Один `Document` в `App`. Вкладка в UI одна (с крестиком-заглушкой),
`Ctrl+N`/`Ctrl+O` заменяют текущий документ (с проверкой несохранённых изменений).

**Последствия.** Простая модель состояния и кэшей. Мультидокументность — задача
ROADMAP v0.6, потребует рефакторинга: `Vec<DocumentSession>` + активный индекс,
кэши текстур с ключом по документу.

## ADR-013 · Тёмная тема фиксируется принудительно

**Контекст.** В egui 0.33 стиль выбирается по `ThemePreference::System`. На Windows
со светлой системной темой приложение получало светлые чекбоксы, слайдеры,
`DragValue` и поля ввода поверх тёмных панелей; из-за другого размера виджетов
меню-бар обрезался, а чекбоксы наезжали друг на друга. `theme::apply` вызывается
из `App::new`, когда системная тема ещё не определена, поэтому правки уходили в
`dark_style`, а активным оказывался `light_style`.

**Решение.** В начале `theme::apply` — `ctx.set_theme(ThemePreference::Dark)`, затем
чтение `ctx.style()` и все правки. Приложение всегда тёмное, системная тема
игнорируется.

**Последствия.** Все стандартные виджеты используют палитру из `theme.rs`, скриншоты
совпадают на светлой и тёмной ОС. Светлая тема приложения не поддерживается.
Если появится переключатель темы — сначала прочитать этот ADR и проверить, что
стили пишутся в активную тему.
