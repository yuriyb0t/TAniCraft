# Отладка и проверка

Практическое руководство: как собрать, запустить, снять скриншот и убедиться, что
фича не сломала базовый сценарий. Дополняет [`AGENTS.md`](../AGENTS.md).

---

## 1. Сборка

```powershell
cargo build                  # debug
cargo build --release
cargo check                  # быстрее, без линковки
```

Проект: Rust edition 2024, `eframe`/`egui` 0.33.x (см. ADR-001). Обновление
`egui` требует переписать UI — не делать «просто так».

### PowerShell и код возврата

Cargo пишет предупреждения в stderr. Из-за этого PowerShell может показать
`Exited with code 1`, хотя сборка успешна. Ориентир — строка `Finished`. Чистый код
возврата:

```powershell
cargo build 2>$null; $LASTEXITCODE      # 0 = успех
```

Число предупреждений не должно расти. Текущий ориентир — 13 (см. TASKS, T-020).

### Типичные ошибки

| Симптом | Причина / что делать |
|---|---|
| `linker not found` / `link.exe` | Нет MSVC Build Tools; установить «Desktop development with C++» |
| `failed to run custom build command` для `eframe` | Нет OpenGL-драйверов или старый GPU-драйвер; обновить драйвер |
| Окно не появляется, процесс висит | Проверить `target\debug\tanicraft.exe` вручную, посмотреть консоль |
| `error: edition 2024 is unstable` | Старый toolchain; `rustup update stable` |
| Сборка «успешна», но бинарник старый | Процесс запущен и держит exe; закрыть `tanicraft` и пересобрать |

## 2. Запуск

```powershell
cargo run
# или
Start-Process .\target\debug\tanicraft.exe
```

Перед пересборкой закрыть запущенный экземпляр, иначе Windows не даст перезаписать
exe:

```powershell
Stop-Process -Name tanicraft -ErrorAction SilentlyContinue
```

Минимальный размер окна — 1040×680; проверять вёрстку нужно и на нём, и на
дефолтном 1480×930.

## 3. Скриншот (основная проверка UI)

Юнит-тестов на отрисовку нет, поэтому визуальная проверка обязательна.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\screenshot.ps1
```

Скрипт:

1. ищет процесс `tanicraft` с реальным окном (≥ 320×240);
2. если процесса нет — запускает `target\debug\tanicraft.exe` и ждёт окно до 20 с;
3. разворачивает окно, если оно свёрнуто, и выводит на передний план;
4. берёт границы через `DwmGetWindowAttribute` (без невидимой тени);
5. сохраняет PNG и печатает путь.

По умолчанию: `%TEMP%\opencode\tanicraft.png`. Другой путь:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\screenshot.ps1 -Out shots\ui.png
```

Дальше PNG открывается инструментом `read` — модель видит изображение. Сверять с
[`UI_GUIDE.md`](UI_GUIDE.md), чек-лист — в конце этого файла.

### Если скриншот пустой / 16×16

- Окно ещё не создано: скрипт уже фильтрует окна меньше 320×240 и ждёт; если
  запускаете вручную — добавить паузу.
- Приложение свёрнуто в трей/на другой виртуальный рабочий стол — развернуть.
- Захват идёт с физического экрана: окно должно быть видимым, не перекрытым.
  Другие окна поверх попадут в кадр.
- DPI: скрипт вызывает `SetProcessDPIAware()`; при нестандартном масштабе
  (125/150 %) размеры в пикселях будут больше логических — это нормально.

### Если виджеты белые на тёмных панелях

Это не вёрстка, а системная светлая тема egui. `theme::apply` должен вызывать
`ctx.set_theme(ThemePreference::Dark)` **до** `ctx.style()`. См. ADR-013.

## 4. Проверка `.tcraft` без приложения

Манифест лежит после 12-байтного заголовка (`TACRAFT1` + `u32` длина JSON):

```powershell
$b = [IO.File]::ReadAllBytes("project.tcraft")
[Text.Encoding]::ASCII.GetString($b[0..7])            # TACRAFT1
$len = [BitConverter]::ToUInt32($b, 8)
[Text.Encoding]::UTF8.GetString($b[12..(11 + $len)])  # JSON
```

Что проверить в JSON: `version = 1`, размеры, `fps`, количество слоёв, `kind`
кадров (0/1/2), индексы `image`. Полная схема — [`FILE_FORMAT.md`](FILE_FORMAT.md).

Размер файла грубо: `JSON + Σ PNG`. Если ключевых кадров много, а файл подозрительно
маленький — возможно, кадры сохранились пустыми (`image: null`).

## 5. Ручной тест-сценарий (smoke)

Выполнять после изменений в `doc.rs`, `canvas.rs`, `timeline.rs`, `app.rs`.

### Рисование и undo

1. Новый документ (Ctrl+N) → Brush (B) → нарисовать штрих.
2. Проверить, что кадр стал `Keyframe` (Properties → FRAME), а не остался пустым.
3. `Ctrl+Z` — штрих исчез; `Ctrl+Shift+Z` — вернулся.
4. Ластик (E) → стереть часть штриха; undo возвращает пиксели.
5. Нарисовать на Hold-кадре → должен создаться новый ключевой кадр (ADR-006).

### Таймлайн

1. F6 — новый ключевой кадр с копией рисунка; F7 — пустой ключевой.
2. F5 — Hold перед следующим ключевым, видимый рисунок не меняется.
3. Shift+F5 — удаление кадра; Shift+F6 — key → hold/empty.
4. Drag плейхеда по линейке; `←`/`→`; `Home`/`End`.
5. Двойной клик по не-ключевому кадру создаёт ключевой.
6. ПКМ по кадру — контекстное меню работает.
7. Play (Enter) — анимация идёт с fps документа, Stop останавливает.

### Слои

1. New Layer / Duplicate / Delete / перемещение вверх-вниз.
2. Скрыть слой (eye) — рисунок пропадает с холста, но остаётся в файле.
3. Заблокировать слой (lock) — рисование не начинается, статус объясняет почему.

### Файлы

1. Save As → `test.tcraft`; закрыть приложение; открыть файл.
2. Сверить: имя, размеры, fps, число слоёв, кадры и рисунки на месте.
3. Export Frame PNG (Ctrl+E) → PNG с фоном документа.
4. Изменить документ → закрыть вкладку/окно: должен появиться диалог
   сохранения (сейчас окно ОС закрывается без диалога — известный баг T-003).

### Undo-цепочка (обязательно)

1. Штрих → F6 → F7 → удалить слой.
2. `Ctrl+Z` ×4 — состояние шаг за шагом возвращается.
3. `Ctrl+Shift+Z` ×4 — всё восстанавливается, текстуры не «залипают».

## 6. Чек-лист визуальной проверки

- [ ] Меню читается целиком (`File … Help`), пункты не обрезаны.
- [ ] Все стандартные виджеты тёмные (чекбоксы, слайдеры, поля ввода).
- [ ] Панели не перекрываются; таймлайн на всю ширину.
- [ ] Активный инструмент подсвечен, курсор соответствует инструменту.
- [ ] На таймлайне различимы key / hold / blank key / empty.
- [ ] Плейхед виден на линейке и в сетке, счётчик кадра совпадает.
- [ ] Диалоги центрированы, кнопки справа, Esc/крестик закрывают.
- [ ] При 1040×680 текст не выходит за панели, ничего не наезжает.
- [ ] В статус-баре осмысленная подсказка, а не пустота.

## 7. Где искать причину

| Что сломалось | Файл |
|---|---|
| Рисование, зум, пан, он-скины, текстуры холста | `src/canvas.rs` |
| Кадры, слои, undo, меню, шорткаты, playback | `src/app.rs` |
| Отрисовка/клики таймлайна | `src/timeline.rs` |
| Модель, `.tcraft`, PNG, resize | `src/doc.rs` |
| Диалоги и «сохранить?» | `src/dialogs.rs` |
| Стиль и цвета | `src/theme.rs` |
| Общие виджеты | `src/ui.rs` |
| Иконки | `src/icons.rs` |

Полезные точки останова: `App::exec` (какая команда пришла), `App::commit` /
`App::push_pixels` (что попало в undo), `App::texture_for` (почему текстура
перезагрузилась), `Layer::effective_key` (какой кадр реально виден).
